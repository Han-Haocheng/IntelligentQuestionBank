## 占位符约定

- 统一使用全角方括号【】标记**待人工填写/核实**的内容，例如【学校名称】【成员A·姓名】。
- 成稿前请全文搜索【 逐一替换；不要把占位符直接提交给评委或申报单位。
- 通用占位符（多文件重复出现）：
  - 【学校名称】 / 【学院/专业】 / 【成员A/B/C·姓名与分工】 / 【指导教师】
  - 【申报/比赛名称】 / 【申报日期】 / 【演示日期与场合】
  - 【经费与定价假设】类占位符：所在段落均为“规划/假设”，填写前请团队确认口径。
- 同一份材料中同一事实（日期、数字、名称）须全文一致。

## 使用与一致性提醒

1. **“规划 ≠ 已取得”**：04 号文档明确标注了哪些是“已有”、哪些是“未取得/规划中”。申报材料中不得把规划写成业绩；专利/软著/检测报告等只有在真正取得证书或报告后才能作为“已取得”材料使用。
2. **提交记录口径**：仓库 git 提交记录显示的提交账号以 han-haocheng 为主（另有少量 ggt）。若申报材料写明“三人共同开发”，建议三人的实际贡献记录与 git 作者信息可对应（可用 `git config user.name/user.email` 各自提交或提交时注明 co-authored），避免“口头三人、记录一人”的口径不一致。
3. **开源许可与权属**：仓库为 MIT 许可（版权人 Han-Haocheng）。MIT 授权他人使用代码，不等于团队内部/学校对成果的权属划分；高校项目如需申请软著或参与竞赛，请按学校规定确认成果权属与署名顺序。
4. **数字时效**：提交数（95）、测试数（193）、Release 列表等为口径日期数据，引用时请注明“截至某日”，答辩前如有新提交请更新。
