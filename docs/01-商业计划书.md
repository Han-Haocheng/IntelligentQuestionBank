## 1. 执行摘要

**一句话**：一套集「管题—练题—分析」于一体的智能题库软件——老师用几分钟把 Excel 里的旧题变成可检索、可共享、可练习的在线题库；学生刷题自动判分、错题自动沉淀、AI 生成个人学情报告；数据私有化部署、自主可控、开源免费。

| 项目 | 内容 |
| --- | --- |
| 产品形态 | B/S 网页系统 + Electron 桌面端（Windows/macOS/Linux）+ 服务端渲染轻量版（qbank-web） |
| 当前阶段 | 已发布 v1.0.0 ~ v1.3.0-beta.1 共 8 个版本（2026-08-29 ~ 2026-09-03），核心闭环全部可用 |
| 目标用户 | 教师/培训讲师、学生/备考人群、教育机构与院校管理员 |
| 差异化 | 开源免费 + 私有化部署 + 数据自主可控 + AI 不绑定厂商（自选任意 OpenAI 兼容大模型或本地模型） |
| 商业模式（规划） | 开源版免费；未来规划：SaaS 托管订阅、私有化部署授权、机构定制服务（详见第 7 章，尚未实施） |

## 2. 项目背景与市场痛点

### 2.1 背景

题目是教与学的核心生产资料，但多数中小学校、培训机构与个体教师的题目资源仍以 Word/Excel/纸质文件散落管理，缺乏系统化沉淀。教育信息化的下沉需求真实存在，但商业平台存在费用高、数据不自主、绑定生态等问题。

### 2.2 痛点（团队在校园与教学场景中的观察，待补充调研来源【调研佐证：可附问卷/访谈记录】）

1. **建题难**：把历史试卷/表格整理成结构化题目耗时巨大，缺乏一键批量导入手段。
2. **练题散**：学生练习分散在纸质卷、各类 App，练习数据不成体系，错题不复盘。
3. **反馈慢**：交卷不能即时判分，教师无法及时掌握班级薄弱点。
4. **数据孤岛与不自主**：题目存在商业平台后被锁定；学校数据（学生练习数据等）难以导出与自主管控。
5. **AI 用不起来**：通用大模型不适合直接做题库工具；商业产品 AI 功能绑定自家模型与订阅，私有化/开源场景几乎空白。

### 2.3 市场规模（**假设区**，需引用第三方数据补全，例如教育部统计的各级学校数、培训机构数、题库类产品付费用户规模等）

## 3. 产品与服务

### 3.1 产品定位

面向教师与学生群体的**私有化、开源、AI 增强**的题库与练习系统。产品把“管题（录入/导入/分类/共享）— 练题（练习/判分/错题/收藏）— 分析（统计/AI 报告）”串成完整闭环。

### 3.2 用户角色（现状为系统内置两级角色）

| 角色 | 能力（均为已实现功能） |
| --- | --- |
| 管理员 | 用户管理（增/禁用/重置密码/删除）、全局二级分类管理、界面主题管理、全站/指定用户统计查看、全部题目/题库/共享查看 |
| 普通用户 | 建题建库、批量导入、练习、错题本、收藏、共享协作（发出/接收）、本人统计与 AI 分析、资料维护；普通用户可见收到的共享内容并遵守只读/可编辑权限 |

> 真实使用中“教师建题、学生刷题”是用法分工，系统本身为两级权限模型，未按“教师/学生”做账号区隔（如需，可在管理端用户管理中按组区分，属规划项）。

### 3.3 功能全景（均已实现，截至 v1.3.0-beta.1）

| 模块 | 功能要点 |
| --- | --- |
| 题目管理 | 单选/多选/填空/判断/简答 5 种题型；难度(1-5)、知识点标签、二级分类、题库归属；关键词检索、分页；增删改与批量删除 |
| 批量导入 | Excel(.xlsx)/CSV（UTF-8 与 GBK 兼容）批量导入；下载模板（按题型三种模板 + 非模板化）；三步向导（上传→预览校验→导入），错误行标红跳过；事务化 + 失败行隔离；预览时可 AI 补全缺失的答案与解析 |
| 练习 | 顺序/随机/错题重做三种模式；按分类/题库/题型/难度筛选；练习中不展示答案防作弊；交卷自动判分；练习记录与详情 |
| 判分引擎 | 单选/多选/判断精确匹配；填空多空以分隔符判分；简答宽松匹配（规则确定性、可审计，详见 docs/03） |
| 错题本 | 答错自动入本并累计错误次数；标记掌握/恢复/移除；错题重练；可收藏错题 |
| 收藏 | 一键收藏/取消，收藏夹分页 |
| 共享协作 | 题目/题库共享给指定用户或公开；只读/可编辑两级权限（可编辑可写回共享者原记录）；订阅（实时跟随）/退订/拷贝为本人副本（记录来源）；管理员可查看全部共享 |
| 统计看板 | 题目/分类/收藏/错题/练习总览；题型与难度分布；近两周正确率趋势；易错分类 Top5；管理员可按用户/全站筛选 |
| AI 分析 | ①导入补全 ②单题质量分析 ③个人学情报告（详见第 5 章与 docs/03-AI技术应用说明.md） |
| 界面主题 | 管理员维护多套前端样式（主色/侧栏/顶栏/背景/圆角等），内置 3 套种子主题；用户可自行切换；个人选择存本机 |
| 系统/安全 | 注册登录、JWT 鉴权 + 服务端会话白名单（重启失效）、BCrypt 密码哈希、登录限流、越权校验、CORS 可配置、异常信息脱敏 |
| 桌面端 | Electron 打包 Windows(exe)/macOS(dmg)/Linux(AppImage/deb)；登录页可配置远程后端地址 |
| 轻量版 | qbank-web：SpringBoot+Thymeleaf 服务端渲染版（分类/题库/题目管理 + 练习与错题本页面），低资源环境可选部署 |

### 3.4 核心价值主张

- **对教师/机构**：一次导入即建成题库；与同事共享协作出题（可写回合并）；班级学情一目了然；系统可部署在校内服务器，数据不出校。
- **对学生**：即时判分、错题自动沉淀、AI 学情报告给出薄弱点与练习建议，形成“练—错—补”的正向循环。
- **对学校信息化部门**：全开源可审计、无商业平台绑定、可定制可二次开发。

## 5. AI 能力（本计划书摘要，详见专项说明 docs/03-AI技术应用说明.md）

1. **AI 导入补全**：批量导入预览时，对缺答案/解析的行调用大模型补全（单次 ≤ 50 行），结果写入预览可人工编辑后入库，失败行提示人工补充。
2. **AI 题目质量分析**：对单题分析“考查知识点 / 难度(1-5)及理由 / 表述清晰度与改进建议 / 解题思路提示（不直接给完整答案，防刷题作弊）”。
3. **AI 学情报告**：基于本人统计数据（正确率、错题分类、趋势）生成总体评价、薄弱点、学习建议与练习计划。

**AI 架构与边界（核心卖点之一）**：AI 调用由**前端浏览器直连用户自选的大模型服务商**完成（Key 存用户本机浏览器，不落本项目服务器），因此：
- 支持 DeepSeek/OpenAI/阿里云百炼/智谱/Kimi/SiliconFlow 等任意 OpenAI 兼容服务，或本地 Ollama（数据完全不出内网）；
- 题目内容只在该用户点击“分析/补全”时发送，系统无隐式上传、无批量收集；
- 判分、权限、统计等核心逻辑全部为确定性代码，**AI 不参与任何自动决策、不直接修改数据库**（详见 03 号文档的伦理与可解释性章节）。

**愿景（规划）**：基于现有闭环进一步实现智能组卷与个性化出题（见第 9 章路线图）。

## 6. 竞争分析

### 6.1 主要竞争/替代类别（分类事实来源于项目方调研视角）

| 类别 | 代表（举例） | 与本项目差异 |
| --- | --- | --- |
| 商业在线题库平台 | 学科网、猿题库等 | 免费开源、可私有化、数据自主；功能聚焦“自建题库 + 练习闭环”而非内容售卖 |
| 问卷/表单工具 | 问卷星等 | 本项目聚焦“练与学”完整闭环：自动判分、错题本、学情统计、共享协作，而非表单收集 |
| 各校/机构自建系统 | 校内旧题库系统 | 本项目交付即用（一键初始化）、开源可改、含 AI 增强，维护成本低 |
| 通用大模型聊天工具 | ChatGPT/DeepSeek 等 | 本项目将 AI 与“题目管理—练习数据”结合（基于用户真实练习数据的学情报告），并提供题库工作流 |

### 6.2 差异化总结

1. **开源免费 + MIT**：可自由使用、修改、商用，无供应商锁定。
2. **私有化部署、数据自主**：MySQL 单库即可跑通，适合校园内网/信创环境（规划适配信创需补国产化数据库适配验证【待验证】）。
3. **AI 开放接入**：不绑定模型厂商；Key 归用户、直连第三方，甚至可接本地模型实现数据不出域。
4. **产品克制、闭环完整**：不做大而全的内容商城，把“导入—练习—错题—报告”做到位。
5. **工程化完整**：自动化发布、版本记录、193 项单元测试、数据库幂等脚本——中小团队产品少见的工程成熟度。

### 6.3 竞争风险（如实说明）

本项目当前**不内置版权题库内容**（内容由用户自己导入），与内容型平台（学科网等）不是同一竞争维度——这是刻意选择（规避版权与内容运营门槛），也意味着**获客不能靠内容，要靠工具口碑与场景渠道**（见第 8 章）。
