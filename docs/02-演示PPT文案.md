## P2 痛点

**页标题**：题目那么多，为什么还是“难出、难练、难复盘”？

**要点（可直接抄）**：
1. 建题难——纸质试卷/Excel 表格手工整理，一门课几十上百题，动辄一两天；
2. 练题散——练习分散在纸质卷和不同 App，错题不复盘、数据不成体系；
3. 反馈慢——交卷无即时判分，老师难以及时掌握班级薄弱点；
4. 数据不自主——商业平台建题库易进难出，学校数据无法私有化管控；
5. AI 用不上——通用聊天大模型不是题库工具，商业平台的 AI 又绑定订阅。

**口播**：我们观察到的第一个事实是：对老师来说“出题”是专业活，但“管题”是体力活；对学生来说“刷题”是常态，但“错题复盘”几乎没有工具支撑；而机构一旦把题库放进商业平台，数据和 AI 能力都绑定了厂商。痛点其实集中在三个字——**散、慢、绑**。

## P3 产品一句话与价值

**页标题**：一套“管题—练题—分析”完整闭环的开源题库系统

**一句话**：集题目管理、练习判分、数据洞察与 AI 增强于一体的私有化智能题库软件。

**要点**：
- 老师端：Excel 一键导入建库 → 共享协作出题 → 班级学情洞察；
- 学生端：即时判分 → 错题自动沉淀 → AI 学情报告 → 针对性补漏；
- 部署端：开源免费、可私有化部署，数据自主可控，AI 自由接入不绑定厂商。

**口播**：一句话概括——这是一套把“管题、练题、分析”做成完整闭环的题库软件。老师几分钟把 Excel 旧题变成在线题库；学生练完即时判分、错题自动进本；在此基础上，AI 提供质量分析与个人学情报告，而且所有数据都可以部署在学校自己的服务器上。

## P4 功能全景

**页标题**：五大能力，覆盖教与学全流程（建议六宫格/图标排版）

**要点（每条一行）**：
1. 题目管理：5 种题型 · 难度/标签/二级分类 · 检索分页
2. 批量导入：Excel/CSV 模板导入 · 错误行标红 · AI 补全答案与解析
3. 练习闭环：顺序/随机/错题重做 · 交卷自动判分 · 错题本自动沉淀
4. 共享协作：题目/题库共享 · 只读/可编辑权限 · 订阅实时跟随/拷贝副本
5. 数据洞察：统计看板 · 正确率趋势 · 易错分类 Top5 · 管理员全站视角
6. 个性体验：多套界面主题 · 桌面三平台客户端 · 服务端渲染轻量版

**口播**：系统按六个模块组织：题目管理覆盖五种题型和完整元数据；批量导入支持 Excel/CSV，错误行自动标红，缺失的答案和解析还能用 AI 补全；练习提供顺序、随机、错题重做三种模式，交卷自动判分，错题自动进入错题本；题目和题库支持共享协作，细到“只读/可编辑”两级权限；统计看板给每个学生和老师图形化的数据反馈；最后是体验层：主题皮肤、三平台桌面客户端、以及给低配服务器准备的服务端渲染轻量版。

## P6 Demo ② 练习→判分→错题（现场演示，1.5 分钟）

**页标题**：Demo 2 —— 练完即判、错题自动沉淀

**操作路径**：切换到普通用户 demo → 题库/练习页选择分类与题型 → 开始练习（界面不显示答案）→ 交卷 → 立即看到判分结果 → 错题本查看自动收录与错误次数 → 标记掌握/错题重练。

**口播**：学生端的练习体验是这样的：可以选择顺序、随机或错题重做，练习过程中界面故意不显示答案，防止边做边抄；交卷后系统用确定性规则自动判分——单选多选判断精确匹配、填空按空给分、简答宽松匹配。答错的题自动进错题本并累计错误次数，下次可以直接“错题重做”。对备考来说，这个闭环的价值是：**每一次做错的题都不会再丢**。

## P8 共享协作与主题（现场演示/截图，1 分钟）

**页标题**：老师之间的“共享协作”，学生自己的“个性化界面”

**要点**：

## P9 技术架构与工程化

**页标题**：技术架构与工程化（建议放架构简图：浏览器/桌面端 → Spring Boot API → MySQL；AI 支路直连模型服务商）

**要点**：
- 前端 Vue 3 + Element Plus + ECharts；后端 Spring Boot 3 + MyBatis + MySQL 8；
- Electron 桌面端：Windows / macOS / Linux 三平台打包；
- 安全：JWT + 服务端会话白名单（重启失效）、BCrypt 密码、登录限流、越权校验；
- 工程化：GitHub Actions 自动构建发布；8 个 Release、版本自动管理；
- 质量：后端 17 个测试类 193 个单测；数据库脚本幂等可重跑（初始化与升级分离）；
- AI 支路：前端浏览器直连用户自选大模型（见 P10）。

**口播**：技术选型以成熟、可维护、可私有化部署为原则：Vue3 + Spring Boot + MySQL 是国内团队最熟悉的组合，教师机房的老机器也带得动；安全上做了一整套加固——JWT 加服务端会话白名单、BCrypt 密码、登录限流、越权校验，这些都在 changelog 里有对应记录。工程化方面，我们搭了完整的自动发布流水线：推标签自动构建三平台安装包并发布 Release，目前已经发布了 8 个版本；后端有 17 个测试类、193 个单测覆盖核心业务。作为一个学生项目，我们用“工程化”而不是“demo 化”的标准要求自己。

## P10 数据安全与 AI 隐私设计（重点页，建议评委提问准备）

**页标题**：数据自主可控 × AI 隐私设计

**要点**：
1. 可私有化部署：学校可部署在内网，题目与练习数据不出校；
2. AI 由用户自己配置服务商与 Key，**Key 只存本机浏览器，不上传本项目服务器**；
3. 仅用户点击分析/补全时，才把**当前单题文本或统计摘要**发送给大模型，无隐式收集；
4. 支持本地大模型（Ollama），需要数据完全不出内网时可选；
5. AI 不参与自动决策：判分、权限、入库全为确定性代码，AI 输出仅为“建议/草稿”，人工确认后生效；
6. 无 Key 不影响全部核心功能——练习、判分、统计完全可用。

**口播**：这是评委可能会问到的隐私问题，我们提前设计了答案。第一，系统可以整体部署在校园内网，这是商业 SaaS 给不了的；第二，AI 调用不走我们的服务器，用户在“AI 设置”里填自己的 API Key，Key 保存在本机浏览器；只有当用户点“分析”或“补全”的那一刻，当前这一道题或一组统计摘要才会发给用户自己选的服务商；如果不允许任何题目出校，还可以配本地模型 Ollama，一行都不出内网。第三，也是最关键的一条：**系统里没有任何一个环节是 AI 自动做决定的**——判分、权限、写库全部是确定性代码，AI 的输出永远停留在“建议”层，人工确认后才生效。

## 附录 A：现场 Demo 操作脚本（对照真实系统走查）

> 演示前请按此清单预演 2~3 遍，并准备备用机/备用网络。演示数据来自 db/init.sql 种子数据。

**准备**
1. 本机启动后端（`java -jar qbank-*.jar` 或 IDE 运行）与前端（`npm run dev`），或直接用 Electron 桌面端；确认 MySQL 已导入 init.sql。
2. 浏览器分别准备好两个会话：admin（管理员）、demo（普通用户）。
3. AI 演示前在 demo 账号“我的 → AI 设置”完成服务商/Key 配置并“测试连接”成功（若现场网络不稳，准备跳过 AI 补全的备份方案）。
4. 准备 1 个含十几道题、其中 3~5 行缺答案/解析的 xlsx 测试文件。

**第 1 步（对应 P5）**：admin 登录 → 题目管理 → 新建 1 题（展示录入表单）→ 批量导入 → 下载模板/选测试文件上传 → 预览页指出标红错误行 → 勾选“AI 补全”→ 展示结果 → 修改其中一行（体现人工可改）→ 完成导入 → 列表验证条数。
